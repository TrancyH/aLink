# 05 - 安全与隐私设计

> 状态:设计定稿(v1.0,2026-10-26)
> 关联:[02-系统架构设计](./02-系统架构设计.md) · [03-核心技术方案](./03-核心技术方案(scrcpy协议与ADB通路).md) · [04-伴侣APK设计(二期)](./04-伴侣APK设计(二期).md)
> 一句话原则:**本地优先、数据最小化、零云端;能不上报的不上报,必须落盘的都加密,用户随时可删。**

## 1. 设计原则

1. **零云端**:一期不依赖任何云端服务(无账号、无遥测、无云同步);二期同样零云端,配对与传输全部发生在局域网 / USB。
2. **信任锚点唯一且用户可见**:一期信任锚 = 手机端 USB 调试授权;二期信任锚 = QR 配对 + 6 位比对码。两条链路互不混淆。
3. **最小权限**:桌面端与 APK 均按功能触发式申请权限;不用的能力协商位为 0。
4. **明文即风险**:默认假设"线上的都是可被截获的"——一期 USB 通道明文是已知限制(见 §4.1),敏感功能在二期全部走 mTLS。

## 2. 威胁模型(STRIDE 简表)

S=伪装假冒 T=篡改 R=抵赖 I=信息泄露 D=拒绝服务 E=权限提升

| # | 威胁场景 | STRIDE | 入口/前提 | 一期(ADB)缓解 | 二期(APK)缓解 | 残余风险 |
|---|---|---|---|---|---|---|
| 1 | 局域网嗅探 / 中间人 | S T I | 与手机同网的攻击者抓包 / ARP 欺骗 | 不适用(一期走 USB)或受限(无线 adb 本身明文,见 §4.1) | mTLS 1.3 双向认证;6 位 SAS 比对在配对期击穿 MITM;会话票据单次使用防重放 | 手机/电脑任一端被完全入侵后可发起会话 |
| 2 | 恶意桌面端(连过一次的电脑) | S E I | 公共电脑 / 被入侵电脑曾获信任 | 手机端"撤销所有 USB 调试授权"引导(§3) | 手机端"忘记此电脑"吊销单台证书;吊销指纹防 TOFU 重绑(04 §4.4) | 用户不及时吊销前的窗口期 |
| 3 | 恶意 USB 主机(充电桩 / 借电脑) | S E | 手机插入攻击者控制的 host | 手机弹出 RSA 指纹确认框,未授权即拒绝;调试授权默认"仅本次/永久"由用户勾选 | 不依赖 USB 调试,插电仅充电;APK 通道不因 USB 插入而建立 | 用户在指纹框上盲目点"允许" |
| 4 | 剪贴板内容泄露 | I | 剪贴板含密码/验证码,同步后驻留两台设备 | 剪贴板历史默认关闭;自动同步可设手动;验证码类内容(正则识别)默认不同步并提示 | 同左;二期剪贴板历史端到端加密存储(§3.2) | 用户主动开启历史且设备失窃(受 Keychain/DPAPI 保护) |
| 5 | 通知敏感信息 | I | 验证码短信、聊天内容随通知同步到桌面 | 通知文本脱敏开关(默认仅 App 名+标题);按 App 免打扰 | 同左;`NotificationEvent.text` 在脱敏模式下于手机侧置空后才出网(04 §5.2) | 用户关闭脱敏时的桌面侧泄露面 |
| 6 | 物理接触(拿到电脑/手机) | S T R I D E | 设备未锁屏或磁盘可离线读取 | 本地数据全加密(§3.2);配对私钥不出 Keychain/DPAPI、Keystore | 同左;丢失手机可从电脑吊销档案,反之亦然 | 设备本身未设锁屏密码 |
| 7 | 本机恶意软件(与 AmooLink 同机) | S I E | adb server 端口被复用 / 本地文件被读 | adb server 仅绑 127.0.0.1(§3);Electron 多进程沙箱(§7) | 同左 | 操作层恶意软件可读用户会话(任何桌面应用同等风险) |
| 8 | 传输文件被篡改 | T D | 中间人改写传输内容(仅二期网络路径) | 不适用(USB 点对点) | 每文件 sha256 整体校验(`FileChunk.last=true` 时核对,04 §5.2);gRPC 层 TLS 防在线篡改 | — |

不在范围内(明确排除):手机/桌面操作系统自身被 root/提权后的防御;针对 scrcpy 协议实现内存安全的内存破坏类漏洞(按常规 fuzz 与代码评审缓解)。

## 3. 一期(ADB)信任模型

### 3.1 RSA 指纹授权机制

- 桌面端首次运行时,`@u4/adbkit` 使用内置 adb 密钥库(`~/.android/adbkey`)生成 **RSA 2048** 密钥对;
- USB 插入后手机 adbd 向桌面发起质询,桌面用私钥签名;
- 手机端弹出"**允许 USB 调试吗?**"对话框,展示电脑密钥的 **RSA 指纹(MD5:xx:xx:…)**,用户勾选"一律允许使用这台计算机进行调试"并确认后,公钥写入 `/data/misc/adb/adb_keys`;
- 此后该电脑与手机的所有 adb 会话免确认,直到用户显式撤销。

### 3.2 AmooLink 的边界与防护

| 事实 | AmooLink 对策 |
|---|---|
| adb server 仅监听 `127.0.0.1:5037`(adbkit 同样仅本地回环) | 不开启 `adb -a` / 不做 `adb tcpip` 暴露到网络的引导;无线场景一律走 **Android 11+ 无线调试配对(`adb pair`,自带 TLS+PIN)** 或二期 APK mTLS |
| **授权过的电脑可永久调试**:任何持有该密钥的进程都能 shell 读写共享存储、安装 APK、截屏 | 设置页提供"**撤销所有 USB 调试授权**"引导入口:说明文案 + 深链 `adb shell am start -a android.settings.APPLICATION_DEVELOPMENT_SETTINGS`;并在"关于安全"页解释撤销后需重新指纹确认 |
| USB 上的 adb 协议本身**不加密**(见 §4.1) | 敏感内容(剪贴板历史等)落盘加密;文档明示"USB 数据线视为物理可信边界" |
| scrcpy-server 以 shell 身份运行,权限=uid 2000 | 仅从内嵌资源推送,启动前校验 SHA-256(§6.2),不执行任何外部来源的 jar |

## 4. 数据最小化与本地化

### 4.1 总览

- **一期零云端**:无账号系统、无遥测、无崩溃上报(默认)、无更新检查(或仅用户手动触发且直连 GitHub Releases 并校验签名);
- 所有功能数据仅存于两台设备本地;
- 网络面只有:USB 本地回环(5037/adb)、USB 设备通道、mDNS 局域网组播(二期)。

### 4.2 剪贴板历史

| 属性 | 设计 |
|---|---|
| 默认状态 | **关闭**;开启需在设置页显式打开并展示用途说明 |
| 存储 | 仅本地:macOS `~/Library/Application Support/AmooLink/clipboard.db`,Windows `%APPDATA%\AmooLink\clipboard.db` |
| 加密 | **AES-256-GCM**:每条记录随机 12 字节 nonce,AAD 绑定记录元数据(时间戳、类型);DEK 为 32 字节随机密钥,以 OS 钥匙串包裹存储——macOS **Keychain**(kSecClassGenericPassword,仅当前用户,访问触发 ACL 询问),Windows **DPAPI**(CryptProtectData,用户作用域) |
| 保留期 | 默认 7 天,可选 1/7/30/90 天,启动时自动修剪;上限 500 条滚动淘汰 |
| 同步范围 | 历史记录**永不上传/不跨设备同步**(二期端到端加密同步为独立可选功能,默认关闭) |
| 验证码防护 | 命中验证码特征(4–8 位数字+字母、含"验证码/OTP"上下文)的条目默认不同步且历史中保留 60 秒后删除 |

### 4.3 通知脱敏

- 设置项"通知脱敏"默认开启:转发到桌面的通知**仅包含 App 名称与标题**,正文字段(`NotificationEvent.text`)在**手机侧置空后才出网**(二期),一期则在桌面侧解析 dumpsys 时丢弃正文;
- 按 App 免打扰黑名单:黑名单 App 的通知完全不同步(含标题);
- 桌面侧通知不进入任何持久化历史(除非用户开启"通知记录",该记录同样走 AES-256-GCM 本地加密)。

## 5. 传输安全

### 5.1 USB ADB 不加密的说明

- adb 协议(USB bulk 传输)只有认证(RSA 签名质询)而**无加密**——认证保护"谁能连",不保护"线上内容";
- 意味着:物理接触 USB 链路(串入 hub / 硬件抓包)或入侵主机内核可观测 scrcpy 视频流、文件块、shell 输出;
- 缓解立场:USB 物理通道在威胁模型中按"用户可控物理边界"处理(§2 #6 之外的场景不针对);对明文通道上传输的敏感数据(剪贴板正文)在**落盘层**加密,传输层机密性由二期 mTLS 提供;一期文档与设置页如实告知用户该边界。

### 5.2 伴侣 APK:mTLS 1.3

| 项 | 设计 |
|---|---|
| 协议版本 | TLS 1.3(禁用 1.2 及以下;Android 10+ / Node 18+ 原生支持) |
| 证书 | 双方各持 **P-256 ECDSA** 自签名身份证书(04 §4.3),配对时交叉登记指纹;无第三方 CA 依赖 |
| 双向认证 | 每个方向都校验"对端证书指纹 ∈ 已配对列表",任何一方不在列表即断开并计入安全日志 |
| 会话恢复 | **会话票据(PSK resumption)**:ticket key 每 6 小时轮换、票据单次使用防重放;恢复连接不降级认证强度(需同时携带对端证书指纹校验) |
| 套件 | `TLS_AES_256_GCM_SHA384` / `TLS_AES_128_GCM_SHA256`;ALPN `amoolink/1` |
| 媒体流 | 与控制面同一 TLS 上下文的独立连接(裸 socket + scrcpy 帧格式),不引入明文端口 |

### 5.3 mDNS 隐私

- 广播实例名使用**随机设备别名**(如 `Sapphire-Falcon-42`),配对后别名固定但可随时在手机端"重置别名";
- TXT 记录仅含 `v`(协议版本)与 `fl`(能力标志位),**不含**序列号、机型、IMEI、MAC、Android 版本;
- QR 码(04 §4.1)同样只携带别名与地址;
- 桌面端设备档案中记录"别名 ↔ 证书指纹"映射,敏感标识(真实序列号)仅存在内存会话与用户可见的设备详情页,默认不写入磁盘档案(写入时仅存哈希)。

## 6. 供应链安全

### 6.1 许可证合规(Apache-2.0)

| 组件 | 许可 | 合规动作 |
|---|---|---|
| `scrcpy-server.jar`(内嵌) | Apache-2.0 | 仓库保留其上游 `LICENSE` 与 `NOTICE` 全文(`resources/third-party/scrcpy/`);应用"关于"页展示版权与许可;发布物(安装包)内附带许可文本 |
| `@u4/adbkit` | Apache-2.0 | `NOTICE` 随 `node_modules` 保留;构建脚本将依赖清单许可证导出到"关于 → 开源许可"页 |
| 其他依赖 | 各自 | `pnpm licenses list` 生成清单入包;CI 检查无 GPL 类传染性许可进入发布物 |

### 6.2 二进制校验(SHA-256 清单)

- `resources/checksums.json` 记录所有随包二进制的 SHA-256:`scrcpy-server.jar`、macOS/Windows 平台 adb 二进制;
- 校验时机:**构建时**(CI 比对上游 release 校验值)、**运行时**(MirrorService 推送 scrcpy-server 到手机前校验一次,失败即拒绝启动并报错);
- 下载走国内镜像(npmmirror / Electron 镜像)时,**镜像只作分发渠道,校验值一律锚定上游官方 release 公布的哈希**,防镜像篡改;
- 哈希清单文件本身纳入 git 版本控制与代码评审。

### 6.3 更新安全

- macOS:Developer ID 签名 + 公证(Notarization)+ Hardened Runtime;keychain 存放的私钥永不入库;
- Windows:Authenticode 签名;electron-updater 在安装前**验证新包签名与出版者一致**,不匹配即中止;
- 拒绝降级:更新清单带最低版本号,防回滚攻击;
- `pnpm-lock.yaml` 提交仓库,`pnpm audit --prod` 进 CI;发布物生成 SBOM(cyclonedx)存档。

## 7. 权限治理(桌面端 Electron 加固)

### 7.1 窗口与进程隔离

```ts
// 主进程:所有窗口统一安全基线
const win = new BrowserWindow({
  webPreferences: {
    contextIsolation: true,          // 渲染层与 Node 语境完全隔离(必须)
    nodeIntegration: false,          // 渲染进程禁用 Node(必须)
    nodeIntegrationInWorker: false,
    sandbox: true,                   // 渲染进程 Chromium 沙箱(必须)
    webviewTag: false,               // 禁用 <webview>(必须,不嵌任意网页)
    enableWebSQL: false,
    spellcheck: false,
  },
});
// 禁止渲染进程导航到外部源;外链一律经确认后走系统浏览器
win.webContents.on('will-navigate', (e, url) => {
  if (!url.startsWith('file://')) e.preventDefault();
});
win.webContents.setWindowOpenHandler(({ url }) => {
  if (isAllowedExternal(url)) { shell.openExternal(url); }
  return { action: 'deny' };
});
```

- 不使用 `remote` 模块;preload 仅通过 `contextBridge.exposeInMainWorld` 暴露**类型化、按域分组**的最小 API(`window.amoolink.device.*` 等),每个 channel 白名单校验参数(zod schema);
- IPC 消息在主进程侧同样做 schema 校验与来源窗口校验,拒绝未知 channel。

### 7.2 CSP 策略示例

渲染进程 HTML 由构建期注入(meta 标签与主进程 `session.defaultSession.webRequest.onHeadersReceived` 双重下发):

```
Content-Security-Policy:
  default-src 'none';
  script-src 'self';
  style-src 'self';
  img-src 'self' data: blob:;
  media-src 'self' blob:;              /* 投屏帧经 blob/MediaSource */
  connect-src 'self' ws://127.0.0.1:* http://127.0.0.1:*;
  font-src 'self';
  object-src 'none';
  base-uri 'none';
  frame-src 'none';
  form-action 'none';
  worker-src 'self' blob:';            /* WebCodecs/解码 worker */
```

要点:无 `unsafe-inline` / `unsafe-eval`(样式经 CSS Modules 构建,无运行时 eval);`connect-src` 仅放行本机回环,渲染层无任何外网直连能力。

### 7.3 其他桌面治理

- 危险操作确认:APK 安装、`adb tcpip`、撤销授权引导等动作在 UI 层二次确认;
- 本地剪贴板/通知库文件权限 0600(macOS 亦受 App Sandbox + TCC 约束,若开沙箱则单独申请访问目录);
- 日志脱敏:日志中的设备序列号/号码/剪贴板正文一律替换为 `sha256 前 8 位` 或 `<redacted>`。

## 8. 隐私合规清单

### 8.1 数据清单(收集了什么 / 存在哪 / 保留多久 / 如何删除)

| 数据类别 | 是否收集 | 用途 | 存储位置 | 保留期 | 删除方式 |
|---|---|---|---|---|---|
| 设备信息(型号、Android 版本、电量、连接方式) | 是(连接期间) | 设备面板展示、能力判断 | 内存会话;设备档案仅存别名+证书指纹+型号哈希 | 会话结束即弃;档案随"移除设备"删除 | 设置 → 设备管理 → 移除;或一键清除 |
| 设备序列号 | 是(ADB 必需,连接标识) | adb 寻址 | **仅内存**,不落盘档案(日志中脱敏) | 会话 | 无需删除(从未持久化) |
| 剪贴板历史 | 仅用户开启后 | 本地历史回贴 | 本地 AES-256-GCM 加密库(§4.2) | 默认 7 天滚动 | 设置 → 剪贴板 → 清空历史 / 关闭并清空 / 一键清除 |
| 通知内容 | 转发不存储(默认) | 桌面弹窗 | 内存瞬时;可选"通知记录"走本地加密 | 默认不存;开启后 7 天 | 设置 → 通知 → 清空记录 |
| 短信 / 通讯录 | 按需拉取缓存 | 面板展示 | 内存会话缓存(≤5 分钟 TTL) | 会话 | 断开即清;无落盘 |
| 传输文件 | 用户主动收发 | 文件互传 | 接收目录(用户可见普通文件) | 用户自管理 | 文件管理器手动删;一键清除仅删临时目录 |
| 配对凭据(证书/私钥/指纹) | 是 | mTLS 认证 | macOS Keychain / Windows DPAPI;Android Keystore | 长期(至吊销/轮换) | 双方各自的"移除设备 / 忘记此电脑";一键清除可选连配对身份一并删 |
| 运行日志 | 是(本地) | 排障 | `userData/logs/`(脱敏) | 7 天滚动 | 一键清除 |
| 崩溃/遥测上报 | **默认关闭** | — | 无 | — | 无数据可删 |

### 8.2 一键清除所有本地数据

设置 → 隐私 → **"清除所有本地数据"**,执行前展示完整删除清单并要求二次确认(输入 `DELETE` 或等效强确认):

1. 剪贴板历史库(含加密密钥包裹项)与所有缓存;
2. 通知记录(若开启);
3. 设备档案、证书信任列表(可选勾选:同时吊销本机配对身份并通知已连接手机);
4. 临时传输目录、缩略图缓存;
5. 运行日志;
6. 保留项(明示):用户设置(仅重置隐私相关项)、接收目录中已完成的文件(属用户文件,列出路径供手动处理)。

执行完成后展示删除摘要;手机端对应提供"忘记此电脑"(吊销单台)与"重置身份"(吊销全部,04 §4.4)。卸载应用时同样弹出提示引导先执行一键清除。

### 8.3 合规口径

- AmooLink 为本地工具类软件,无账号体系、无第三方 SDK 嵌入(无统计/广告/追踪 SDK),天然满足"不向任何服务器传输用户数据";
- 涉及他人个人信息(短信、通讯录、通知)的功能在 UI 层标注"请仅在合法授权场景使用";
- 隐私声明内置于"关于"页与首次启动向导,与本文档同步更新。
