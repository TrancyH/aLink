## 2. M0 工程骨架

### 2.1 目标

搭建可持续交付的工程底座:pnpm monorepo、Electron 应用壳、`packages/adb` 中 DeviceService 的**真实实现**(非 mock)、可运行的设备页 UI 框架,并以真机 PZ261A 完成首次端到端验证。

### 2.2 任务分解(WBS)

| 编号 | 任务 | 主要产出 | 人日 |
| --- | --- | --- | --- |
| M0-1 | monorepo 脚手架 | pnpm workspace(apps/desktop、packages/adb、packages/scrcpy-client)、TS project references、ESLint/Prettier、Vite 基线、CI(lint + typecheck) | 2 |
| M0-2 | Electron 壳 | electron-vite 集成、主/预加载/渲染三层结构与 CSP、窗口管理、托盘骨架、自动更新占位 | 3 |
| M0-3 | packages/adb(DeviceService 真实实现) | @u4/adbkit 封装:trackDevices 插拔事件、USB transport、属性读取(型号/代号/Android 版本/SDK)、电量(dumpsys battery)、存储与连接方式判定 | 4 |
| M0-4 | 类型安全 IPC 与状态 | 主/渲染 typed IPC 契约、React 状态管理、设备域模型与事件流 | 2 |
| M0-5 | 设备页 UI | 设备列表 + 设备面板(型号、Android 版本、电量、存储、连接方式、序列号),事件驱动刷新 + 30s 轮询兜底 | 4 |
| M0-6 | 构建与打包 | electron-builder(mac dmg / win nsis)、`pnpm typecheck` / `pnpm build` 脚本、图标与签名占位 | 2 |
| M0-7 | 冒烟测试与说明文档 | 真机冒烟清单、开发文档 | 1 |
| | **合计** | | **18** |

### 2.3 交付物

1. 可 `pnpm dev` 运行的桌面应用骨架(双平台)。
2. `packages/adb` v1.0:设备发现、插拔事件、属性/电量/存储读取 API。
3. 设备页(实时设备列表与面板)。
4. CI 流水线(lint / typecheck / build)与开发文档。

### 2.4 验收标准

1. **`pnpm dev` 启动后,设备页实时显示真机 PZ261A(代号 pandora)的型号、Android 版本(Android 16)与电量**;USB 接入 ≤3s 出现,电量随手机实际变化刷新。
2. **`pnpm typecheck` 全仓库通过(零错误)**。
3. **`pnpm build` 全仓库通过**,并产出 mac dmg 与 Windows exe 安装包,安装后设备页功能正常。
4. 拔出 USB ≤5s 列表移除,再插入自动恢复;USB 未授权状态有明确引导文案。
5. 同时接入 2 台设备(1 真机 + 1 模拟器)列表不串扰。

### 2.5 风险与对策

| 风险 | 对策 |
| --- | --- |
| @u4/adbkit 对 Android 16 新版 adb 协议兼容性未知 | M0 第一周即在 PZ261A 真机验证握手/授权/trackDevices;若不兼容,引入平台工具 adb 二进制作为降级通路(见风险登记 R-03) |
| Electron 多平台构建链路耗时超预期 | M0 即打通双平台 CI 产物,后续里程碑增量演进 |

## 3. M1 投屏

### 3.1 目标

交付产品核心体验:基于自研 scrcpy client 协议与 WebCodecs 硬解的低延迟投屏,含完整鼠标/键盘反控、参数调节、窗口形态、黑屏模式与多设备同投。

### 3.2 任务分解(WBS)

| 编号 | 任务 | 主要产出 | 人日 |
| --- | --- | --- | --- |
| M1-1 | scrcpy-server 分发 | 内嵌固定版本 scrcpy-server.jar、push 至 `/data/local/tmp`、app_process 拉起与参数拼装 | 3 |
| M1-2 | 协议客户端(packages/scrcpy-client) | socket 对建立、设备元信息与版本解析、视频帧通道、control 消息编码(inject touch/key/text、set screen power、剪贴板事件) | 6 |
| M1-3 | WebCodecs 渲染管线 | H.264/H.265 VideoDecoder、时间戳与丢帧策略、Canvas(WebGL)渲染 | 4 |
| M1-4 | 反控 | 鼠标五类手势→触摸/按键事件、键盘与文本注入、快捷键(Home/返回/多任务/音量/锁屏/亮屏) | 4 |
| M1-5 | 参数与 OSD | 分辨率/码率/帧率/编码器 UI 与透传;FPS 与码率实时统计 | 2 |
| M1-6 | 窗口形态 | 独立窗口、置顶小窗、全屏、旋转自适应 | 2 |
| M1-7 | 黑屏模式与多设备同投 | set screen power 通路、多会话管理 | 2 |
| M1-8 | 测试与延迟基准 | 反控用例清单自动化、延迟测量方法(计数器+慢动作) | 1 |
| | **合计** | | **24** |

### 3.3 交付物

`packages/scrcpy-client` v1.0;投屏窗口(全形态);反控与快捷键;参数与 OSD;延迟基准测试报告。

### 3.4 验收标准

1. PZ261A(USB)1080p / 60fps / 8Mbps 端到端延迟 <100ms。
2. 《投屏反控测试用例清单》全部通过(单击/双击/长按/拖动/滚轮/键盘/全部快捷键)。
3. 旋转、黑屏模式、多设备同投满足 FR-02 验收(旋转自适应 ≤2s,双投各 99 分位 ≥55fps)。
4. 连续投屏 1 小时内存增量 <10%(无泄漏)。
5. 分辨率/码率/帧率切换即时生效。

### 3.5 风险与对策

| 风险 | 对策 |
| --- | --- |
| scrcpy 协议随 server 版本演进(音频通道、control 消息变更) | 固定内嵌 server 版本并锁定校验和;client 侧协议版本适配层;升级 server 必须跑回归矩阵(见 R-01) |
| WebCodecs 在 WKWebView / WebView2 的能力与行为差异 | 渲染层抽象 Decoder 接口 + 启动时能力探测;H.265 不可用时自动回落 H.264;CI 双平台指标采集(见 R-02) |

| 编号 | 风险 | 类别 | 影响 | 概率 | 缓解措施 |

## 9. 排期与并行建议

1. **人力配置**:2 人全职(A:资深桌面/Electron,主 M0–M4;B:全栈 + Android,主 M2/M5 并支援 M1/M3)。
2. **并行点**:M1 与 M2 均只依赖 M0,可并行;M5 依赖 M0/M3,可与 M4 并行。
3. **缓冲**:每个里程碑按估算 +15% 缓冲;M1(协议攻坚)与 M4(驱动签名)为高不确定段,各预留 1 周弹性。
4. **发布节奏**:M4 结束即发布一期 GA(免装 App 全功能);M5 结束发布二期(伴侣 APK)。
5. **质量门禁**:每里程碑退出必须满足:验收标准全过、双平台冒烟通过、PZ261A 首过验证、无 P0 级未解缺陷。
