# 08 · 笔记模块设计(M6)

> 目标:参考 vivo 原子笔记,提供 AmooLink 桌面端笔记模块 + Android 端笔记 App,
> 手机连接电脑后自动双向同步(可开关),数据格式开放(Markdown),永因同步丢内容。

## 1. 选型

| 项 | 决策 | 理由 |
|---|---|---|
| 编辑器内核 | **Tiptap v3**(MIT) | headless 可自绘 vivo 风工具栏;ProseMirror 生态最大;纯客户端离线;同一套 React 组件复用于 Electron 与 Android WebView |
| 数据格式 | **Markdown + frontmatter** | 每条笔记一个 `.md`;同步=文件同步,可 diff、可兜底、任何编辑器可打开 |
| 本地存储 | `userData/notes/*.md` | 仓库无 SQLite 先例;纯文件零 native 依赖,与同步格式天然一致 |
| 手机端 | **Kotlin WebView 壳**(`apps/android-notes`) | 编辑器 bundle 放 assets 离线运行;该 APK 兼作 docs/04 伴侣 APK 的首个模块 |
| 同步通道(一期) | **ADB**(adbkit push/pull) | 手机侧目录 `/sdcard/Android/data/com.amoolink.notes/files/notes/`——app 读写自己外部目录免权限,adb 可直接读写,其他 app 不可见 |
| 同步通道(二期) | M5 伴侣 APK mTLS 通道 | 按 docs/04 §6 Transport 抽象替换数据源 |

对比落选:Lexical(生态小、同效果代码量大)、Milkdown(框架绑定深)、Quill(架构老)、
Tiptap Pay 云协同(本项目同步自研,不需要)。Markdown 序列化用社区包 `tiptap-markdown`,
若失维护可替换——序列化隔离在 `packages/notes-editor` 内部。

## 2. 数据模型

### 2.1 笔记文件

```markdown
---
id: 20261027-143201-a1b2c3        # 时间戳+随机后缀,双端生成不冲突
title: 会议纪要                    # 冗余存标题(正文首行也会被解析)
createdAt: 2026-10-27T06:32:01.000Z
updatedAt: 2026-10-27T06:40:12.000Z
pinned: false
---

正文 Markdown(Tiptap 存储)…
```

### 2.2 同步清单 manifest.json(两端各持一份)

```json
{
  "version": 1,
  "notes": {
    "<id>": { "md5": "…", "mtime": 1730000000000, "deletedAt": null }
  }
}
```

- **删除 = tombstone**:`deletedAt` 置时间,30 天后物理清理;防"删了又被同步回来"
- md5 全小写 hex;mtime 为该端最后写入时间

## 3. 同步协议(文件级双向)

### 3.1 触发时机

1. 设备上线(`wireServices` 编排,照 notify-service 模式)
2. 设备在线期间桌面每 5s 轮询:`execOut cat <manifest>` 比对,有差异才传输
3. 用户手动点「立即同步」
4. `settings.notes.autoSync` 开关(默认开)关闭时,仅手动触发生效

### 3.2 比对规则(对每个 id,取 local/remote 两个状态)

| local | remote | 动作 |
|---|---|---|
| 有内容 md5A | 无记录/已删 | push A |
| 无记录/已删 | 有内容 md5B | pull B |
| md5A | md5B(A≠B) | **冲突**:双方各留副本——本端内容另存 `<title>-冲突-yyyyMMdd-HHmm.md`,拉入对端内容,两端最终一致 |
| md5A | md5A | 无动作 |
| 已删 t1 | 已删 t2 | 保留较新 tombstone |

约束:同步期间 UI 显示状态机 `idle→scanning→syncing(n↑/m↓)→done/error`,
全程逐文件事务(先写临时名再 rename),任何一步失败状态置 error 不中断其余文件。

### 3.3 手机端目录

```
/sdcard/Android/data/com.amoolink.notes/files/
  notes/*.md
  manifest.json
```

真机若遇 `/sdcard/Android/data` 对 adb 限制(部分 ROM),退路:
`run-as com.amoolink.notes`(debug 包)或 ContentProvider;实现隔离在 sync 适配层。

## 4. 桌面端 UI

- 全局侧栏新增「笔记」→ `/notes`,两栏(已有全局侧栏,无需 vivo 的第三栏):
  - **左列表**:搜索框、新建按钮、置顶图钉、卡片=标题+摘要(正文首行纯文本)+相对时间;
    顶部同步状态条(如「已同步 · 5s 前」/「同步中 ↑2 ↓1」/「冲突 1」)+「立即同步」
  - **右编辑**:Tiptap 编辑区,单行工具栏(粗体/斜体/删除线/H2/H3/无序列表/有序列表/待办/引用/代码),
    标题即正文首个 heading?否——**标题独立输入框**(与 vivo 一致),正文从非标题起;
    500ms 防抖自动保存,底部显示字数与更新时间
- 设置页「通用」分组新增开关:自动同步笔记(手机连接后自动双向同步)
- 样式全部走 `tokens.css` 变量,深浅色自动适配

## 5. 工程落点

```
packages/notes-editor/          # workspace 包(源码直引,照 @amoolink/adb 模式)
  src/types.ts                  # NoteMeta / NoteFile / Manifest
  src/frontmatter.ts            # parseNote/serializeNote/stripMarkdown(纯函数,单测)
  src/editor.tsx                # TiptapNoteEditor React 组件 + createAndroidMount(非 React 挂载)
  src/android-main.ts           # WebView 壳专用入口(无 React,挂载编辑器+JS 桥协议)
  vite.android.config.ts        # IIFE 单文件 bundle → apps/android-notes/app/src/main/assets/editor/
apps/desktop/src/main/services/note-service.ts   # 本地 CRUD + 同步引擎(单例)
apps/android-notes/             # Kotlin WebView 壳(FileObserver + JS Bridge)
```

IPC:`amoolink:notes:list/get/save/create/remove/pin/syncNow/status/installApp`
(照 `amoolink:<domain>:<action>` 约定;preload + env.d.ts 三处同步)。
设置:`AppSettings.notes = { autoSync: boolean }`。
