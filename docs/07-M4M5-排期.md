# M4/M5 排期:虚拟摄像头与伴侣 APK

> 状态:规划(2026-10-27)。M4 其余项(音频/录屏/H.265/应用面板/托盘自启/无线)已在本轮完成。

## 一、虚拟摄像头(M4-3,建议 6-8 人日)

**目标**:手机摄像头作为 macOS/Windows 系统级摄像头,供 Zoom/腾讯会议/浏览器使用。

**技术选型(macOS 优先)**

| 方案 | 原理 | 优劣 |
|---|---|---|
| A. DaluSoft/OBS 虚拟摄像头集成 | 检测已安装的 OBS Virtual Camera,把视频帧写共享内存 | 零驱动开发,依赖用户装 OBS;最快落地 |
| B. CMIO DAL 插件(系统扩展) | 自研 CoreMediaIO DAL 插件注册系统摄像头 | 原生体验;需 Apple 签名+公证+SystemExtension 流程,周期长 |
| C. 旧式 DAL(不沙盒) | 传统 CMIO 插件 | macOS 12+ 弃用,不推荐新开发 |

**建议**:先做 A(1-2 人日,检测 OBS + 帧注入),B 作为正式版方案并行申请开发者账号签名资质。
Windows 侧用 MediaFoundation 虚拟摄像头(参考 softcam/unity-capture 开源方案,需驱动签名,约 3 人日)。

**实施顺序**
1. 手机端 camera 源:scrcpy `video_source=camera`(v3.3.1 已支持,Android 12+;StepX 满足)——协议层改动小,session 加 camera 参数即可(0.5 日)
2. macOS 检测 OBS 虚拟摄像头并写入帧(通过 obs-websocket 或共享内存;1-2 日)
3. UI:投屏工具条「作为摄像头共享」开关(0.5 日)
4. Windows 驱动(独立排期)

## 二、伴侣 APK(M5,建议 25 人日,docs/04 已有完整设计)

| 子项 | 内容 | 人日 | 依赖 |
|---|---|---|---|
| M5-1 工程骨架 | Kotlin + 前台服务 + 保活 | 3 | Android Studio 工程 |
| M5-2 mTLS+QR 配对 | 证书互换、扫码配对、局域网直连(替代 ADB) | 5 | M5-1 |
| M5-3 通知快捷回复 | NotificationListenerService + RemoteInput | 5 | M5-2(数据通道) |
| M5-4 短信/通讯录 | ContentProvider 读取 + vCard 导出 | 4 | M5-2 |
| M5-5 系统右键菜单 | macOS Services / Windows「发送到手机」 | 3 | 桌端配套 |
| M5-6 剪贴板历史 E2E | 加密存储 + 多机中继 | 3 | M5-2 |
| M5-7 来电提醒 | 电话状态监听 + 电脑静音 | 2 | M5-2 |

**建议启动顺序**:M5-1 → M5-2(打通免 ADB 通路,价值最大)→ M5-3(通知回复是最高频诉求)→ 其余并行。

**前置条件**:Android Studio 环境 APK 签名证书(调试期 debug key 即可)。
